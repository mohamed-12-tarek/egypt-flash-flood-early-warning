# 🎯 Risk Scoring
### كيف بيتحسب `risk_score` و`risk_level`

المرجع الفعلي للكود: `spark/silver_to_gold_load.py`. الأرقام اللي هنا هي القيم الحالية، وهي **قيم مبدئية قابلة للمعايرة** (راجع القسم 6).

---

## 1) الفكرة العامة

الخطورة بتتحسب لكل (مدينة، ساعة) من 3 مكونات، بأوزان:

| المكون | الوزن | بيعبّر عن |
|---|---|---|
| **Rainfall hazard** | 0.60 | شدة المطر الحالية والمتراكمة قصيرة المدى |
| **Antecedent condition** | 0.25 | رطوبة الأرض المسبقة (مطر 72 ساعة + تشبع التربة) |
| **Terrain** | 0.15 | القابلية للسيول بسبب الميل والارتفاع |

```
risk_score = round( 100 × ( 0.60·hazard + 0.25·antecedent + 0.15·terrain ) )     ∈ [0, 100]
```

---

## 2) المعادلات

كل مدخل بيتحوّل لقيمة بين 0 و1 بدالة ناعمة (smooth normalization):

```
norm(x, ref) = 1 − exp(−x / ref)
```

| المكون | المعادلة |
|---|---|
| Rainfall hazard | `0.35·norm(rain_1h, 15) + 0.25·norm(rain_3h, 30) + 0.15·norm(rain_6h, 45) + 0.25·norm(rain_24h, 60)` |
| Antecedent condition | `0.60·norm(rain_72h, 80) + 0.40·norm(soil_moisture, 0.5)` |
| Terrain | `0.70·norm(slope_degree, 30) + 0.30·exp(−elevation / 1600)` |

| الثابت | القيمة | الوحدة |
|---|---|---|
| `rain_1h` reference | 15 | مم |
| `rain_3h` reference | 30 | مم |
| `rain_6h` reference | 45 | مم |
| `rain_24h` reference | 60 | مم |
| `rain_72h` reference | 80 | مم |
| `soil_moisture` reference | 0.5 | m³/m³ |
| `slope` reference | 30 | درجة |
| `ELEVATION_REFERENCE_METERS` | 1600 | متر |

مجموع أوزان كل مجموعة = 1، والـ score بيتقص في [0, 100] وبيتحول لـ `INT`.

---

## 3) مستوى الخطورة (`risk_level`)

القيم المعتمدة بالإنجليزي (نفس النص بالحرف في كل الكود): `Safe` · `Watch` · `Danger` · `Severe Danger`.

```
لو rain_sum_24h < 1 مم           →  Safe          (مفيش مطر تقريبًا = مفيش سيل)
غير كده:
    risk_score <  P80            →  Safe
    P80 ≤ risk_score <  P95      →  Watch
    P95 ≤ risk_score <  P99      →  Danger
    risk_score ≥ P99             →  Severe Danger
```

### العتبات P80 / P95 / P99
- بتتحسب من صفوف الـ **historical** فقط (`source = 'historical'`) **اللي فيها `rain_sum_24h ≥ 1` مم** (الساعات المطيرة).
- بتتحسب بـ `approxQuantile` وبتتسجل في اللوج كل تشغيل: `Historical thresholds: P80=…, P95=…, P99=…`.
- الـ job بيفشل لو: مفيش ساعات مطيرة تاريخية، أو العتبات خارج [0, 100]، أو مش مرتبة. ولو عتبتين اتساووا بيطلع warning.

### ليه الـ gate والـ percentiles على الساعات المطيرة؟
في مناطق صحراوية أغلب الساعات جافة. لو العتبات اتحسبت من كل الساعات، هتطلع أرقام صغيرة جدًا (حوالي P80=10, P95=12, P99=17 في اختبار محاكاة)، فالفروق الثابتة في التضاريس والتربة بس كانت هتتصنف `Watch` أو `Danger` من غير ولا نقطة مطر. الـ gate + حساب العتبات من الساعات المطيرة بيحل ده.

---

## 4) التحقق من المدخلات (Data Quality)

قبل الحساب وقبل الكتابة، الـ job بيفحص ويوقف التحميل برسالة واضحة لو لقى:
- مفاتيح مكررة `(city, event_time)` في Silver.
- قيم null أو NaN أو Infinity في أي مدخل.
- قيم سالبة في المطر أو الميل.
- `soil_moisture` فوق 1 (غالبًا خطأ وحدات: نسبة مئوية بدل fraction).
- `risk_level` خارج القيم الأربعة، أو `risk_score` خارج [0, 100].

**حالات خاصة اتعالجت:**
| الحالة | المعالجة |
|---|---|
| `soil_moisture` سالب صغير (ERA5 artifact، مثلًا `-0.015`) | بيتقص لصفر في `clean_bronze_weather` وأيضًا قبل الفحص في `silver_to_gold_load` (علشان الصفوف الموجودة بالفعل في Silver) |
| `elevation` ≤ 0 (نقاط ساحلية) | مسموح؛ بيتفحص إنه رقم صحيح بس |

---

## 5) التشغيل والـ Idempotency

- بيشتغل كل ساعة بعد `live_incremental_job` في الـ DAG `hourly_ingestion`.
- بيقرأ Silver ويحسب كل الصفوف، لكن بيكتب في Gold **الصفوف الجديدة فقط** (anti-join على `city, event_time`)، فإعادة التشغيل مش بتكرر بيانات.
- ⚠️ الصفوف اللي اتكتبت في Gold **ما بتتحدثش** لو اتغيرت العتبات أو المعادلات. بعد أي تعديل في المعادلات: `DELETE FROM gold.fact_hourly_risk` ثم شغّل الـ job.
- القراءة الكاملة لـ Silver كل ساعة مقبولة لحجم المشروع (حوالي 650–800 ألف صف). لو الحجم كبر، الحل هو قراءة الصفوف الجديدة + context بس.

---

## 6) حدود النموذج وخطة المعايرة

هذا نموذج **rule-based** (مش مدرّب على أحداث سيول مسجلة):

1. **المستويات نسبية للتاريخ:** `Watch/Danger/Severe` معناها "أعلى 20% / 5% / 1% من الساعات المطيرة في الـ 5 سنين"، مش عتبات هيدرولوجية مطلقة.
2. **المراجع والأوزان قيم مبدئية** من ملف المشروع، ومحتاجة معايرة بأحداث حقيقية.
3. **عتبات موحدة لكل المدن:** نفس كمية المطر لها أثر مختلف حسب المنطقة.
4. **حد الـ 1 مم** اختياري وقابل للتغيير (`RAIN_GATE_MM`).
5. **آخر 7 أيام من البيانات التاريخية** من Forecast API مش ERA5.

### خطة التحقق المقترحة (Backtest)
1. اختيار 3–5 أحداث سيول موثقة في مصر (التواريخ والمدن من مصادر رسمية).
2. استخراج `risk_score` و`risk_level` لكل ساعة في الأيام دي من Gold.
3. التأكد إن الأحداث الفعلية وصلت `Danger` أو أعلى، وضبط الـ references والأوزان لو لا.
4. تجربة حساسية `RAIN_GATE_MM` عند 0.5 / 1 / 2 مم، وتوثيق ثبات النتائج.
